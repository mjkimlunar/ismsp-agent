# ISMS-P 인증 문의 응답 에이전트

ISMS-P(정보보호 및 개인정보보호 관리체계) 인증 문의를 **카테고리로 나누고 → 그 카테고리의
근거 문서만 열어 → 읽은 내용만으로 답하고 → 검증한다.** 근거를 못 찾으면 답하지 않고
담당 심사원에게 넘긴다.

설계 근거·측정 결과·회고는 **[REPORT.md](REPORT.md)** 에 있다.

| 지표 | 기준선 | 최종 (개선 대상 16건) | 최종 (**전체 20건**) |
|---|---:|---:|---:|
| ① 도구 호출 적절성 | 47.9% | 100.0% | **95.0%** |
| ② 답변 적절성 | 64.6% | 83.8% | **66.7%** |

분류는 경계를 찌르는 문항 32건을 따로 모아 쟀다 (`data/routing_set.json`).

| 분류 지표 | 경계 문항 투입 직후 | 규칙 보강 후 |
|---|---:|---:|
| 정확도 | 0.896 | **0.969** |
| macro F1 | 0.899 | **0.971** |

두 벌로 적는 이유는 개선을 평가셋 16건의 실패만 보고 반복했기 때문이다. 한 번도 열어 보지 않은
4건을 포함하면 ② 가 83.8% → 66.7% 로 떨어진다. **과적합을 확인했고 그대로 보고한다.**

## 빠르게 돌려 보기

```bash
python -m venv .venv
.venv/Scripts/activate            # macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env              # OPENAI_API_KEY 를 채운다

python check_scorer.py            # 채점기 검사 — 모델을 부르지 않아 공짜다
streamlit run app.py              # 데모
```

| 명령 | 하는 일 |
|---|---|
| `python corpus.py` | 근거 문서 410개 조각 구성과 검색 동작 확인 |
| `python context.py` | 카테고리 → 근거 문서 매핑표 출력 |
| `python check_scorer.py` | 모범답안 20개를 통과시키고 함정답안 20개를 잡는지 검사 |
| `python report_routing.py -n 3` | 분류 정확도 · macro F1 · 혼동 행렬 · 오분류 사유 |
| `python evaluate.py -n 5` | 두 지표 측정 (기본 `eval` 16건, `--split all` 로 20건) |
| `python agent.py "문의"` | 문의 하나를 파이프라인에 통과시켜 결과를 본다 |
| `python usage.py` | 지금까지 쓴 토큰과 비용 |
| `streamlit run app.py` | 답변 + 호출 도구 + 근거 조항 + 검증 결과를 한 화면에 |

## 카테고리와 근거 문서

카테고리를 나누는 목적은 문의를 묶는 것이 아니라 **어느 문서를 펼칠지 정하는 것**이다.
기준은 하나다 — *답이 적혀 있는 문서가 다르면 다른 카테고리다.*

| 카테고리 | 문의의 성격 | 근거 문서 |
|---|---|---|
| `MGMT` | 관리체계 수립·운영 (1.x) | 인증기준 1.x · 안내서 · 점검항목 |
| `PROTECT` | 보호대책 요구사항 (2.x) | 인증기준 2.x · 안내서 · 점검항목 |
| `PRIVACY` | 개인정보 처리단계 (3.x) | 인증기준 3.x · 안내서 · 점검항목 · **개인정보 보호법** |
| `CERT` | 인증 제도·심사 절차 | **고시 본문 제17~36조** |
| `OTHER` | 범위 밖 | — (담당자 이관) |

`docs/` 의 근거 문서 3종(410개 조각)은 공개 원문을 내려받은 그대로 두었다.
어느 문서가 어느 카테고리인지는 코드(`corpus.py`)로 표시한다.
원문을 고치지 않아야 나중에 출처를 검증할 수 있다.

## 파이프라인

```
classify ──(확신도)──> assemble ──> retrieve ⇄ tools ──> compose ──> verify ──> 답변
   ①                      ②           ③-1                ③-2         ④
   │                                    │                  │
   └──────────> escalate <──────────────┴── 근거 부족 ──────┘
```

단계를 나눈 이유는 답이 틀렸을 때 **어느 단계가 잘못했는지 특정하기 위해서**다.
한 덩어리 프롬프트면 분류가 틀린 건지 근거가 부족한 건지 알 수 없다.
이 프로젝트의 큰 개선은 전부 원인 단계를 특정한 뒤에 나왔다.

`assemble` 이 근거의 **목차만** 주고 본문은 주지 않는 것이 이 구조의 핵심이다.
본문까지 주면 모델이 도구를 부르지 않고 답해 버려서 근거 추적이 끊긴다.

## 비용

`gpt-4o-mini` 기준 **문의 1건당 약 1.7원** (호출 3.6회 · 입력 7,040토큰).
OpenAI 대시보드는 조직 관리자만 볼 수 있으므로, 호출할 때마다 응답에 딸려 오는
`token_usage` 를 `runs/usage.jsonl` 에 쌓아 직접 센다. `python usage.py` 로 본다.

## 주의
